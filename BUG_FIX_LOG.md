# Bug Fix Log (Stage 1)

Every bug below was reproduced before it was fixed, either by a failing
Playwright test (`tests/grading.spec.js`, test names start with `#N`) or by
the manual steps listed. Fixtures are in `fixtures/` and are generated by
`node fixtures/generate.js`.

| # | Bug / Issue Identified | How You Reproduced It | Root Cause | Fix Implemented | How You Tested the Fix |
|---|---|---|---|---|---|
| 1 | Min and Max statistics are swapped. | Uploaded `valid_basic.xlsx`, selected CS F211 (marks 0–100). The "Min" tile showed 100 and "Max" showed 0. | The markup puts `id="max"` inside the "Min" tile and `id="min"` inside the "Max" tile. `computeStats` writes the smallest mark into `#min`, which is the element labelled "Max". | Swapped the two ids so each label wraps the matching element. | Test `#1`: expects Min = 0 and Max = 100 for CS F211. It failed before the fix and passes after. |
| 2 | Course dropdown lists each course once per student, and a second upload keeps the old courses, grade ranges, stats, histogram, summary and welcome text. | Uploaded `valid_basic.xlsx` (2 courses, 40 rows): the dropdown had 41 options. Each upload clears `data`, trims the select back to its placeholder, calls the reset, and adds one option per distinct course (`new Set`). | Test `#2`: checks the options are exactly the distinct courses after each upload, and that the select, grade UI, summary, welcome, stats, canvas and Download button are all reset after re-upload. | 3 | The file picker only accepts `.xls`, but the brief specifies `.xlsx`. | Inspected the input: test `#3` read `accept=".xls"`. With that value, browsers filter the file dialog to `.xls`, so an `.xlsx` file can only be picked by switching the dialog to "All files". | The `accept` attribute lists only the legacy extension. | Changed it to `accept=".xlsx,.xls"`. SheetJS already reads both formats. | Test `#3` asserts both extensions are accepted (failed before, passes after). Manual check: click "Choose File" and confirm `.xlsx` files are selectable without changing the dialog filter. |
| 4 | Cancelling the file dialog throws an uncaught error. | Uploaded `valid_basic.xlsx` and selected a course, then reopened the dialog and cancelled. On cancel it is `undefined`. | Read the file into `f` and return early if there is none. The guard runs before the reset from #2, so cancelling leaves the loaded data and selected course intact. | Test `#4`: no page errors after an empty `change`, and the courses and selection are unchanged. It failed before the fix and passes after. |
| 5 | Files using the brief's own header wording ("Student's BITS ID", "Total Marks (out of 100)") load with blank marks, and a missing column is never reported. | Uploaded `brief_headers.xlsx` and selected CS F211: the Min/Max tiles were empty and the histogram had no bars. Uploaded `missing_column.xlsx`: the course still appeared and nothing warned that marks were missing. | `sheet_to_json` keys each row by the literal header text, and the code then reads the exact keys `"BITS ID"` and `"Total Marks"`. Any other spelling, case or stray space gives `undefined`. | New `parseMarksSheet()` reads the header row, normalises each header (trim, lower-case, collapse spaces, curly → straight apostrophe) and maps it to a canonical column using an accepted-spellings table (`COLUMNS`). If a column is missing, the upload is rejected with an inline message in a new `#uploadError` element that uses the existing `.error` style. | Tests `#5` (×3): `brief_headers.xlsx` gives the correct stats and export, `messy_headers.xlsx` (`"  bits id "`, `"COURSE"`, `" total MARKS"`) loads, and `missing_column.xlsx` shows "Missing required column: Total Marks" with no courses offered. All failed before the fix and pass after. |
| 6 | Missing, non-numeric or out-of-range marks, blank courses, missing IDs and empty files all load silently. | Uploaded `bad_data.xlsx` (rows with no marks, "abc", -5, 104, a blank course and a blank ID): it loaded with no warning, and the bad rows were silently left out of the histogram, grade summary and CSV. | 7 | Students with decimal marks vanish from the grade summary and the CSV, and the guidance text gives the wrong rounding example (80.2 → 81). | Uploaded `decimals.xlsx` (79.5, 80.2, 49.49, 19.5, 65) and exported. | 8 | Range validation accepts band sets that don't cover 0–100, so students outside them get no grade and vanish from the export. | Uploaded `valid_basic.xlsx`, selected CS F211 (which has a 100) and set A Max to 95: no error, and Download stayed enabled, so the student with 100 would be left out of the CSV. Neither end of the scale (A max, E min) is ever checked. | `validateRanges` first requires A Max = 100 ("Grade A must end at 100.") and E Min = 0 ("Grade E must start at 0."). Together with the continuity check, every integer 0–100 now falls in exactly one band. | Tests `#8` (×2): A Max 95 and E Min 5 each show the error and disable Download. Both failed before the fix and pass after. |
